# 0224. 마을·쉼터 새 그림: 공용 물건 → 큰 나무 → 꾸미기 → 아기 굴토끼

- 날짜: 2026-10-28
- 상태: 제안(범위·순서). 시트 A 첫 시도는 버림(아래 "덧붙임"), 그림체 판으로 다시 — A1·A2 생성은 사장 차례
- 사장: "이제 마을/쉼터의 그림들도 업그레이드 해야겠다"

## 지금(조사, 2026-10-28 코드로 확인)
- **땅·벽**: `terrain.rs`가 지대 팔레트로 점마다 굽는 코드 그림(벽 윤곽·벼랑 면·바닥 띠·얼룩). 위에 찍는 꽃·풀·조약돌은 Sunnyside 팩(없으면 `tiles.png`), 뿌리 덩굴·이끼는 `tiles.png`.
- **물건**: 가게 좌판·모닥불 화덕·그루터기·바위·통나무 자리·마을 꾸미기 넷(꽃밭·버섯·의자·화분)은 팩 그림(+코드 장식). 뿌리 길 입구·저장 버섯 고리·물웅덩이·실 고리·꾸미기 다섯(등·바람종·깃발 줄·병·그네)은 코드 도형.
- **큰 나무**: 코드로 그린 줄기·뿌리 + 팩 나무의 잎 윗부분을 잘라 3/7/10/12개 겹친 잎(자람 1~4), 자람 3부터 코드 분홍 점.
- **이웃**: 모두 새 그림(0216~0220). 다만 토끼풀의 아기 둘은 옛 16칸(`critters.png` 아기 줄).
- 새 캐릭터(24~40칸, 굵은 외곽선)가 팩의 16px 물건 곁에 서면 크기·선 굵기가 어긋난다. 보스·잡몹을 다 갈아입은 뒤라 마을·쉼터가 가장 "옛 그림"으로 남았다.
- 고친 것(조사 중 발견): 지도 마커 목록에 `j`가 빠져 **토끼풀 가족이 마을에 나오지 않았다** — 고침(이 결정과 같은 날).

## 순서(제안)
| # | 묶음 | 왜 이 순서 | 크기(게임 px, 외곽선까지) |
|---|---|---|---|
| A | 공용 물건 여섯: 가게 좌판·모닥불 화덕(불꽃 없이)·그루터기·바위·통나무 자리·뿌리 길 입구 | 쉼터 셋 + 마을 = 런마다 네 번 보는 것. 한 시트로 끝난다 | 30×36 · 24×14 · 16×14 · 22×18 · 20×12 · 40×26 |
| B | **큰 나무** 자람 0~4 다섯 장 | 마을의 얼굴이고 이야기(나무가 다시 핀다)의 진행 표시. 크고 어려워 A로 크기·선을 맞춘 뒤 | 폭 ~110 · 키 ~90 |
| C | 마을 꾸미기 열하나(시트 B 여섯 + 시트 C 다섯, 물웅덩이·실 고리 포함) | 산 사람만 보는 보상 | 8×22 ~ 40×20 |
| D | 아기 굴토끼(서기·깡충) | 작은 것 하나 | 16칸 → 24칸 |

그대로 두는 것: 땅·벽 굽기(지대 팔레트로 이어 붙는 코드라 생성 그림 타일보다 이음매가 없다 — 바꾸려면 타일셋 생성·자동 타일 규칙이 따로 큰 일), 바닥에 찍는 꽃·풀·조약돌(팩, 작은 점이라 어긋남이 적다), 불꽃(팩 4칸 흔들림)·버섯 빛·저장 지점의 빛 기둥·반딧불(효과는 코드가 맞다, 0222와 같은 판단).
