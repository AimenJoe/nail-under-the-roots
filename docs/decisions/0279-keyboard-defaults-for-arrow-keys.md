# 0279 키보드 기본값 = 방향키로 걷는다는 전제 — 동작은 왼손 Z·X·C·V

- 상태: 채택(사장 2026-11-05)
- 관련: 0022(패드 배치·다시 붙이기 — 키보드 기본값만 바꾼다), 0278(보조 키는 거두고 웹 키 입력만 남김), 0036(장치를 따르는 안내)

## 왜
0022는 패드 다이아몬드를 키 J·K·L·I로 옮겼다. 이동이 WASD·방향키 둘 다라, 방향키로 걷는 사람은 이동과 동작이 둘 다 오른손에 몰린다. 0278은 이것을 "동작마다 키 둘"로 풀려 했지만 사장이 거뒀다: "보조를 넣으라는 얘긴 아니었어. best practice도 아니잖아? 괜히 복잡해지기만 하고. 방향키를 사용한다는 전제로 수정해줘."

맞는 말이다. 기본 배치는 **한 손 배치 하나를 정하고** 나머지는 다시 붙이기로 맡기는 것이 보통이고, 기본으로 두 벌을 깔면 조작 설정 화면·겹침 규칙·안내·저장이 다 두 배가 된다. 마우스로 겨누지 않는 2D 액션에서 방향키를 쓰는 관례는 **오른손 방향키 + 왼손 Z·X·C**다(Celeste·Hollow Knight 계열 — 2차 자료, 게임마다 Z·X·C의 뜻은 다르다). 확인·취소도 그 손의 "Z 확인 · X 취소"(Undertale 등 일본식 관례 — 2차).

## 정한 것
| 동작 | 키보드(새) | 키보드(옛, 0022) | 패드(그대로) |
|---|---|---|---|
| 공격 | **Z** | J | X |
| 굴파기(회피) | **X** | K | A |
| 필살기 | **C** | L | B |
| 아이템 쓰기 | **V** | I | Y |
| 이전/다음 아이템 | Q / E | Q / E | LB / RB |
| 지도 | **Tab** | M | Select |
| 메뉴(고정) | Esc | Esc | Start |

- **이동은 방향키**(안내 글 "←↑↓→"). WASD도 그대로 움직인다 — 막을 까닭이 없고, WASD로 걷는 사람은 동작을 J·K·L로 다시 붙이면 된다. 기본 동작 키에 W·A·S·D는 쓰지 않는다.
- **지도는 Tab**: 오른손이 방향키에 있으니 M은 닿지 않는다.
- **메뉴**: 확인 = Enter·Space·공격 키(Z), 뒤로 = Esc·Backspace·**회피 키(X)**. 기본값으로 "Z 확인 · X 취소"가 된다. 다시 붙이면 따라간다(공격 키·회피 키).
- **옛 저장 이관**: prefs 칸 24 = 키 배치 판(0 = 이 결정 전, 1 = 뒤). 판이 0이고 키가 옛 기본값(J K L I Q E M) 그대로면 손대지 않은 것으로 보고 새 기본값. 하나라도 바꿨으면 그대로 둔다. 판 칸이 있으니 다시 옛 기본값을 골라 저장해도 되돌아가지 않는다. 칸을 뒤에 붙였으니 `MAGIC`은 그대로.
- 조작 설정 화면·글은 0278 전으로(두 칸). 고정 안내 글(`ctl_fixed`)만 "방향키·WASD" 순서로(열한 언어).
- 연기 시험·사이트 촬영 스크립트가 누르던 J·K·L → Z·X·C.

## 하지 않은 것
- WASD 이동 빼기: 쓰는 사람이 있고 기본 동작 키와 겹치지 않는다.
- Space를 회피로: Space는 메뉴 확인이고, 방향키 손 관례의 셋째 자리는 C다. 표에 있으니 다시 붙일 수 있다.
- 동작마다 키 둘(0278): 거둠.
