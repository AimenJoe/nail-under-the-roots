# 0070. 점으로 찍는 도트 도구(.pxl)

- 날짜: 2026-10-25
- 상태: 채택(도구만. 게임 그림은 아직 그대로)

## 배경
초상화·일러스트는 `tools/art/*.py`가 타원·구 음영을 쌓아 그린다. 덩어리는 빨리 나오지만 마지막 한 겹이 늘 뭉개진다.
- 윤곽 계단 길이가 들쭉날쭉하다(정수리가 납작하게 뾰족해진다).
- 발톱처럼 작은 부위가 규칙대로 찍혀 "이빨"로 읽힌다.
- 목도리 무늬가 2칸 줄무늬 소음이 된다.

이런 곳은 도형 매개변수로는 못 고치고, 픽셀 몇 개를 직접 놓아야 고쳐진다. 게임 스프라이트(`nail.py` 등)는 이미 글자 격자라 손으로 찍는다. 초상화 크기(88×88)에도 같은 방법이 필요했다.

## 결정
- `tools/pixel/pxl.py`: 텍스트 원본 `.pxl`을 다룬다(팔레트 머리 + 한 글자 = 한 픽셀 격자).
  - `import`: PNG를 `.pxl`로 들여온다(색이 많으면 줄인다).
  - `rekey`: 글자를 뜻 있는 이름으로 바꾼다(`4` = 털4, `O` = 외곽선…).
  - `show`: 좌표 눈금과 함께 한 구역을 출력한다.
  - `put`: 한 줄에 점을 놓는다.
  - `render`: PNG로 그린다(`--zoom --grid`면 확대 미리보기).
  - `sheet`: 여러 장을 한 시트로 잇는다.
  - `check`: 줄 길이·모르는 글자·외톨이 픽셀·**윤곽 계단 검사**를 한다.
- `tools/pixel/editor.html`: 같은 형식을 여는 브라우저 편집기다. 파일 하나에 의존성이 없다.
  - 도구: 연필·채우기·스포이트·좌우 대칭·되돌리기, 실제 크기 미리보기.
  - PNG를 열면 색을 글자로 바꿔 들여온다.
- 작업 순서: 코드 그림(덩어리) → `import` → 점으로 다듬기(사람은 편집기, Claude는 `show`/`put`/짧은 스크립트) → `check` → `render`.
- 다듬은 그림을 게임에 넣기로 하면 `.pxl`이 그 그림의 원본이 된다. PNG는 산출물이라 손으로 고치지 않는다는 규칙은 그대로 둔다. 그때 원본 자리와 생성 경로를 정한다.

## 왜 텍스트인가
- 바이너리 PNG는 diff로 보이지 않는다. `.pxl`은 한 줄 = 한 픽셀 줄이라 바꾼 점이 리뷰에 보인다.
- Claude가 그림을 "보는" 것은 확대 렌더이고, "고치는" 것은 좌표가 분명한 글자 격자일 때 가장 정확하다.
- 사람이 브라우저 편집기로 고친 결과도 같은 파일이라, 둘이 번갈아 손볼 수 있다.

## 계단 검사의 근거
곡선은 계단 길이가 한 방향으로 점점 늘거나 줄 때 매끈해 보인다. 1, 3, 1이나 4, 3, 6처럼 튀면 울퉁불퉁하다. 도트 커뮤니티 튜토리얼들의 공통 규칙이다(2차 출처).
- 검사는 줄마다 실루엣 끝의 이동량을 보고 튀는 줄을 후보로 알린다.
- 귀·볼처럼 일부러 튀어나온 곳도 잡히니 오류가 아니라 후보다.

## 시연(게임에는 넣지 않음)
나일 v2 초상화를 들여와 세 곳을 점으로 고쳤다.
- 정수리 윤곽을 단조 계단으로 바꿨다.
- 목도리를 위에서 아래로 밝음→어둠 네 단에 4칸마다 골이 지게 했다.
- 위로 솟은 크림색 뾰족 발톱을 2×3 평평한 발톱 넷의 부채꼴로 바꿨다.

계단 검사 후보는 5곳에서 2곳으로 줄었다. 남은 두 곳 가운데 오른쪽 하나는 일부러 둔 먼 쪽 귀다. 비교 그림은 세션 임시 폴더에만 있다.

## 추가(2026-10-26): 그림·사진을 도트로(`pxl.py pixelate`)
일러스트는 코드로 도형을 쌓는 것보다, 그림·사진을 바탕으로 도트화한 뒤 손으로 다듬는 편이 나을 수 있다(사장 제안).

순서는 다섯 단계다.
1. 목표 비율로 가운데를 자른다.
2. 대비·채도를 조금 올린다.
3. **한 칸 크기에 맞춘 중앙값 흐림**: 잎·풀·털 같은 잔무늬를 덩어리로 뭉친다. 바로 줄이면 칸마다 색이 튄다.
4. 칸 평균(BOX)으로 줄인다.
5. 색을 줄이고(디더 없음) 외톨이를 정리한다.

색 줄이기는 두 가지 중 하나다.
- `--palette 그림.png`: 그 그림의 색만 쓴다. 게임 그림과 색을 맞출 때 쓴다.
- `--colors N`: 4N색을 뽑은 뒤 가까운 색끼리 합친다. 바로 N색으로 자르면 넓은 면(하늘·풀)이 색을 다 가져가 좁지만 뚜렷한 색(기둥·눈)이 사라졌다.

결과는 `.pxl`이라 그대로 점 다듬기로 이어진다.

원본 그림의 권리는 우리 것이어야 한다. 쓸 수 있는 것은 셋이다.
- 사장이 직접 찍은 사진·그린 그림
- CC0·퍼블릭 도메인
- 상업 사용 가능한 라이선스

`assets/LICENSES.md`에 출처를 적는다. 팩 그림·팩이 보이는 스크린숏은 원본으로 쓰지 않는다(0064). AI 생성 그림은 사장이 정하기 전엔 레포에 넣지 않는다.
