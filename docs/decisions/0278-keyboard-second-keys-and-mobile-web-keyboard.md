# 0278 키보드 다시 보기 — 동작마다 키 둘(방향키 손), 메뉴 뒤로 = 회피 키, 모바일 웹의 실제 키보드

- 상태: **키 배치 부분은 거둠 → 0279**(사장 2026-11-05: "보조를 넣으라는 얘긴 아니었어. best practice도 아니잖아? 괜히 복잡해지기만 하고. 방향키를 사용한다는 전제로"). 웹 키 입력(아래 "웹 키 입력")은 그대로 채택.
- 관련: 0022(배치·다시 붙이기), 0036(장치를 따르는 안내), 0175(설정 저장), KB `concepts/controller-layout-and-remapping.md`(키보드 두 손)·`reference/macroquad/gamepad-and-android-input.md`(실제 키보드, 웹·모바일)

## 왜
사장(2026-11-05): "키보드 초기 설정이 왜 이렇게 되어 있지? 모바일 웹에서 키보드를 연결했는데도 터치로 되어 있고, 설정에 들어가 키를 누르니 그제서야 키보드로 쓸 수 있게 됐다."

1. **배치**: 0022는 패드 오른쪽 넷(X·A·B·Y)을 키 다이아몬드 J·K·L·I로 옮겼다. 패드와 키보드 설명이 같은 그림이 되는 대신 키보드 관례를 보지 않았다.
   - 이동은 WASD와 방향키 둘 다인데 동작 키가 오른손뿐이라 **방향키로 걷는 사람은 손이 겹친다**. 방향키 쪽 관례는 왼손 Z·X·C(Celeste·Hollow Knight 계열, 2차 자료).
   - 메뉴 확인은 Enter·Space·공격 키인데 **뒤로는 Esc·Backspace뿐**이라 손을 옮겨야 한다(`input.rs` 주석의 "필살기 키로 뒤로"는 코드와 달랐다).
   - 접근성 가이드(XAG 107 요약·개발자 가이드)는 다시 붙이기 + 미리 맞춘 배치, WASD·방향키 둘 다를 권한다.
2. **모바일 웹**: 헤드리스 Chromium(폰 화면·터치)에서는 키를 누르면 바로 키보드로 바뀌어 게임 쪽 판정(0036)은 맞았다. 번들(`mq_js_bundle.js`)은 **`canvas.onkeydown/onkeyup`만 듣고 `e.code`로 키를 가른다**. 그래서
   - 포커스가 캔버스 밖(문서 몸통 등)이면 키가 통째로 사라진다 — 터치 처리기가 `preventDefault`라 화면을 짚어도 포커스가 돌아오지 않는다. 헤드리스에서 포커스를 몸통으로 옮기면 그대로 재현됐다(키 0개).
   - Android에서는 실제 키보드 입력도 키보드 앱(IME)을 거치고, 캔버스에 포커스가 있을 때 `code`가 비어 온다는 보고가 있다(ThinLinc 버그 7422 — 원문은 세션에서 못 열어 검색 요약만, emscripten #21960은 가상 키보드의 229 문제). 빈 `code`도 번들에서 사라진다.
   - 사장의 실제 기기·브라우저·키보드 앱에서 어느 쪽이었는지는 **확인하지 못했다**. 둘 다 막는다.

## 정한 것
- **동작마다 키 둘**: 주 키(WASD 손) J·K·L·I / Q·E / M, 보조 키(방향키 손) Z·X·C·V / - · - / Tab. `Bindings::alt`, 빈칸 `NO_KEY`. 한 키는 열네 칸을 통틀어 한 동작에만(겹치면 서로 바꾸고, 빈 보조 칸으로 남의 주 키를 가져오면 그 동작의 보조 키를 주 키로 올린다 — 올릴 것이 없으면 막는다). 시험 `alt_keys_default_and_swap_across_columns`.
- **메뉴 뒤로 = Esc·Backspace + 회피 키(주·보조)**. 확인 = Enter·Space + 공격 키. 키보드 관례 "Z 확인 · X 취소"와 같은 두 손가락. 패드는 그대로(A 확인·B 뒤로).
  - 패드의 거울(뒤로 = B = 필살기 자리 L)이 아니라 회피로 고른 까닭: 보조 키가 Z·X·C 순이라 확인 Z 옆의 X가 취소인 관례와 맞고, 주 키도 J·K가 붙어 있다. 메뉴에서 회피를 누르는 일은 없다.
- **안내는 쓰는 손을 따른다**: 방향키·보조 키를 누르면 `key_hand()` = `Alt` → 걷기 "←↑↓→", 동작은 보조 키 이름(보조가 빈 동작은 주 키). WASD·주 키를 누르면 돌아온다. 메뉴 동사(Enter·Esc)는 그대로.
- **조작 설정 화면 셋째 칸**: 동작 | 키보드 | 보조 | 패드, 좌우로 칸, 같은 "누르세요" 흐름. 글 `ctl_alt` 열한 언어, `ctl_hint`의 "키보드/패드" → "칸". 일본어 `ctl_key` "キー"·러시아어 "Клав."(칸이 좁아져 잘렸다).
- **저장**: prefs 칸 24..31(0 = 칸 없음 → 기본 보조 키, 1 = 빈칸, 번호 + 2). 칸을 뒤에 붙였으니 `MAGIC`은 그대로. 옛 저장은 기본 보조 키 중 주 키와 겹치는 것만 비운다(`Bindings::with_default_alt`).
- **웹 키 입력(`web/nail-host.js`)**: 캔버스를 만지면(`touchstart`·`pointerdown`·`mousedown`)·창이 포커스를 얻으면 캔버스로 포커스. 창 전체 `keydown/keyup` capture에서 **캔버스 밖이거나 `code`가 빈 것만** `key`·`keyCode`(한글 두벌식 자모 포함 — 한글 상태의 "ㅓ" = J)로 `code`를 채워 번들 처리기에 넘긴다. 번들 처리기를 한 번 감싸 같은 이벤트를 빈 `code`로 또 처리하지 않게 한다. 정상인 키는 건드리지 않는다. 연기 시험 `keys:` 두 줄(포커스 밖 → [264]·포커스 돌아옴, 빈 code 넷 → [74,257,75,74] 한 번씩).

## 하지 않은 것
- 첫 장치 짐작(`pointer: coarse` → 터치)은 그대로: 브라우저는 실제 키보드가 붙었는지 알려 주지 않는다(API 없음). 첫 키에서 바뀌는 것이 맞고, 이번 고침은 그 첫 키가 게임에 닿게 하는 것이다.
- Space를 회피 기본값으로: 방향키 손이 X를 써야 해서 셋째 키가 된다. Space는 표에 있어 다시 붙일 수 있다.
- 패드처럼 미리 맞춘 배치(왼손·한 손) 고르기: 키 둘 + 다시 붙이기로 먼저. 요청이 오면.
- 보조 칸 비우기 단추: "기본값으로"와 맞바꾸기로 충분하다고 봤다.
