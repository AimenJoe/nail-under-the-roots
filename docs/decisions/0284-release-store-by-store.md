# 0284. 상점별 출시 — 준비된 상점부터, v1.0에 Epic Android

- 날짜: 2026-11-06
- 상태: **채택**(사장 2026-11-06: "스토어별 출시로 방향을 잡자" → 묻는 창에서 "준비된 상점부터"·"v1.0에 Epic Android 포함"을 골랐다). 0276(v1.0 — Steam 출시)의 범위를 넓힌다.
- 바탕: 0276(v1.0 계획·Epic E1~E5), 0240(PC 빌드), 0005(로컬에 Android SDK를 두지 않는다), 0086(내 기기 시험), 0232·0276 사장 답(레포 공개, 웹·APK 무료 전판 그대로, Steam $0.99 응원값, 상점·Steam 소식에 무료판을 알리지 않는다).

## 정한 것
1. **상점마다 따로, 준비된 곳부터 낸다.** 같은 날 맞추려고 기다리지 않는다. 지금 순서는 Epic PC(업로드·리딤까지 됨) → Steam PC(앱 등록·Coming Soon 2주가 남음).
   - 버전은 하나다. 상점마다 같은 `v1.0.x` 코드를 쓰고, 다른 것은 Cargo 기능(`steam`·`epic`)과 묶음뿐이다(0276 S1·E2). 상점마다 버전을 갈라 따로 고치지 않는다.
   - "v1.0을 닫는다"(release → main + 버전 올리기)는 **첫 상점이 나가는 때**다. 뒤 상점은 같은 v1.0.x 위에서 그 상점의 일(등록·업로드·검토)만 한다.
2. **v1.0 범위에 Epic Android를 넣는다.** 0276의 "Android 정식·iOS TestFlight는 v1.0 밖" 중 **Epic 상점을 거치는 Android만** 안으로 옮긴다. iOS(Epic은 EU에서만)와 Google Play는 그대로 밖이다.

## Epic Android — 조사(2026-11-06)와 모르는 것
- Epic은 2026-03 GDC에서 "2026-08부터 iOS·Android 자체 퍼블리싱"을 발표했다. Android가 먼저 많이 쓰일 것으로 본다. [2차: PocketGamer.biz·gameapps.cc 기사]
- **아직 확인 못 함**: 8월에 실제로 열렸는지, 포털 어디서 하는지(아티팩트 Manage Platforms에 Android가 보이는지), APK·AAB 중 무엇을 받는지, 업적 의무가 모바일에도 있는지, 모바일 상점 그림 규격. 이 세션은 dev.epicgames.com에 닿지 못한다 — 사장이 포털에서 보거나 세션 네트워크에 그 도메인을 허용하면 원문으로 확인한다.

## Epic Android에서 정해야 할 것(사장)
| # | 무엇 | 왜 | 제안 |
|---|---|---|---|
| A1 | 패키지 이름 | 지금 APK는 `io.github.aimenjoe.nail`(개발판 `.nail.dev`). Android는 패키지마다 기록이 따로라, 바꾸면 무료 APK 사용자의 기록이 상점판으로 넘어가지 않고 둘이 나란히 깔린다 | 상점판은 새 이름(예: `io.beardworks.nail`) — 무료 APK와 섞이지 않고, 서명 키도 새로 시작한다. 기록 옮기기는 하지 않는다(Android 기록은 앱마다 갇혀 있다) |
| A2 | 서명 키 | 지금 APK는 **디버그 키**로 서명한다(`build-android.yml`). 상점판은 평생 바꿀 수 없는 정식 키가 필요하다(잃으면 업데이트를 못 낸다) | 정식 키를 새로 만들어 비밀번호와 함께 Environment `store`에만 두고, 사장이 레포 밖에 따로 백업 |
| A3 | 가격·무료판 | PC는 Steam $0.99 응원값 + 무료 웹·APK 그대로. 같은 게임의 무료 APK가 GitHub에 있다 | PC와 같은 원칙: 상점판은 응원값, 무료 APK는 그대로 두고 상점 글에 알리지 않는다 |
| A4 | 조작 | Android 판은 "컨트롤러 필수" 핸드헬드를 겨냥했다(CLAUDE.md). 터치 오버레이는 있다(0172) | 모바일 상점은 터치로 끝까지 할 수 있어야 할 것이라 보고, 터치 한 바퀴 실기를 v1.0 조건에 넣는다(규정 확인 전) |
| A5 | 업적 | PC는 EOS 업적(런처 교환 코드). Android에는 런처가 없어 로그인 방식이 다르다 | 규정이 업적을 요구할 때만 한다. 요구하지 않으면 v1.0에서는 업적 없이 |
