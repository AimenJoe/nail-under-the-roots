# 0191. v0.5.0 마일스톤 "도토와 새 옷": 셋째 플레이어블 도토 + 그림 갈아입기

- 날짜: 2026-10-28
- 상태: **닫음**(2026-10-28, 사장 "0.5.0 배포해줘" → v0.5.0). B1~B5·C1~C5 끝(C3 0206·C4 0216~0221·C5 0222). D(사장 판정)는 배포 결정으로 갈음했고, 남은 확인 칸(새 그림·쓰러짐의 대가·달리기 손맛)은 v0.6(0223)의 첫 조건으로 넘겼다.
- 처음 상태: 채택(범위). B1·B2·B3(0195)·B4(0201)·B5 끝. C1(그림 규칙 0203) 채택, C2 도구(`pxl.py snap`) 끝 — C3 Naïl 첫 시트는 사장 생성 차례.
- 사장: "0.5 마일스톤 생각해 보자" → 후보 A(공개 데모)·B(셋째 캐릭터)·C(그림 갈아입기) 제안 → "**B, C 후 A** 하려고", 버전은 "**B+C를 v0.5로**"(v0.6 = A 공개 데모), 셋째 캐릭터는 "**도토(청설모)**".

## 배경(2026-10-28)
- 플레이어블 둘(Naïl 발톱·굴파기·드릴, 모모 뒷발·깡충·이어 뛰기)은 모두 **근접**이다. 같은 길도 같은 거리에서 싸운다.
- 캐릭터 표(`characters.rs`, 0170 R14)가 있어 새 캐릭터 = 표 한 줄 + 새 회피·특기의 수 + 그림 + 글.
- 스프라이트·타일은 아직 **임시 그림**(코드로 찍은 `tools/art/*.py`). 초상화·일러스트·타이틀은 나노바나나 원본이라, 대화·컷씬보다 싸움 화면이 더 "임시"로 보인다.

## 왜 이 순서
- KB `roguelite-replay-axes`: 다회차의 가장 큰 축이 캐릭터다. 근접 둘 다음은 **거리가 다른 캐릭터**가 가장 새로운 손맛이다. 도토는 보스 수(부채꼴 던지기·높이 뛰기·도토리 묻기, 0052)가 그대로 기술이 된다 — 설계를 두 번 하지 않는다(KB `action-roguelite-for-solo-dev`).
- 그림을 B 뒤에 하면 도토 스프라이트를 임시로 한 번, 최종으로 한 번 만든다. 그래서 **그림 규칙(C1)을 B 구현 전에** 정해 두고, 도토 임시 그림도 그 크기·팔레트로 만든다(갈아입기 비용을 줄인다).
- 공개 데모(A)를 마지막에: 남에게 건넬 때 첫인상이 새 그림이어야 하고, 판정 결과로 고칠 것이 그림이 아니라 게임이게 한다.

- 해금: 도토를 이기고 기억이 돌아오면(`doto_memory`) 마을 뿌리 길 고르기 창에.

## 왜(근거)
- 같은 버튼 자리에 다른 동사(KB `second-playable-character`): 공격·회피·특기 자리는 같고, "멀리서 던지고 물러난다"가 도토의 동사다.
- 그림 규칙을 먼저 두는 것: 여러 번에 걸쳐 생성한 그림이 한 게임처럼 보이려면 크기·팔레트·빛을 숫자로 고정해야 한다(KB `image-model-for-game-illustrations` — 참고 그림 없이 글만 주면 흔한 그림으로 채운다; `pixel-art-without-an-artist` — 값 위계).
