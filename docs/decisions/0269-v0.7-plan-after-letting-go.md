## 0. 조사 방법과 한계
- 조사 범위: 코드(`src/`), 글 표(`src/i18n/ko.rs`), 결정 문서, 그림 도구(`tools/art`), 웹 셸(`web/index.html`), CI(`deploy-web.yml`).
- 조사 방식: 하위 에이전트 셋이 나눠 읽었다. 아래 다섯 가지는 Claude가 코드에서 다시 확인했다.
  - 참 엔딩만 본 기록의 `half_ending` 누락: `app/stage.rs:400-407`.
  - 컷씬 흔들림이 컷씬 동안 돌지 않는 것: `Step::Shake`는 `add_trauma`만 하고, 컷씬은 `tick_fx`만 부르는데 `Feel::tick`은 `World::step`(world.rs:890)에만 있다.
  - 개발 시나리오가 진짜 기록에 쓰는 것: `App::say_story`(app.rs:712-716)가 `recording()` 없이 `profile::save`를 부른다. 꾸미기·짐 사기도 같다.
  - 낡은 안내 글 `h_loot_d`·`ast_go_on_d`: 0259 뒤에도 "쓰러지면 잃는다"가 남아 있다.
  - 공식 페이지 할매 칸: `site/index.html:199`가 정체·결말·엔딩 뒤 역할을 말한다.
- 웹 자료: 사용자 지침대로 PWA는 먼저 바깥 자료로 공부했다. 처음엔 웹 읽기 도구로 web.dev·MDN이 열리지 않아 검색 결과와 Chrome 블로그만 봤다(덧붙임: 셸 `curl`로는 web.dev·MDN·caniuse·webkit.org가 열린다 — 구현 때 1차 문서로 다시 확인한다). 아래 2.4의 플랫폼 사실은 **"2차 출처만 있음 — 실기로 확인할 것"**으로 다룬다.
- 아직 하지 않은 것: 게임을 실제로 띄워 보지 않았다(계획 단계). 검증은 각 단계의 "확인" 칸에서 한다.

### 2.1 누룩에 대한 지나치게 직접적인 힌트 → 이야기(P3)
**설정**(concept.md:19, 0037)
- 보라 "뿌리"는 나무 뿌리가 아니라, 큰 나무보다 오래된 균사 누룩 할매의 실이다.
- 할매는 혼자 남을까 봐 모두를 잇고 있다. 악당은 없고, 끝은 놓아주기다.
- 이를 숨기는 장치(오도)는 "뿌리 독"(잡몹 도감·오프닝), 반대 단서는 실뿌리·"나무 탓만 했어"다.

**직접적인 곳**(세게 드러내는 순)

### 2.4 웹 PWA·가로 전체 화면 → 웹(P2)
**지금**
- 매니페스트·서비스 워커·웹 아이콘이 없다.
- 전체 화면은 PC(`crate::DESKTOP`)만. 세로 화면은 배율 1로 레터박스되어 작게 돈다.
- 배포:
  - `deploy-web.yml`이 `web/`·wasm·`assets/`를 `dist/`로 모아 Netlify에 올린다.
  - 운영 = 루트, 개발판 = `dev--` 별칭, PR = `pr-N--`. 셋은 출처(origin)가 달라 저장소·서비스 워커가 섞이지 않는다.
- `nail.wasm`·에셋 이름에 해시가 없다. 그래서 오래 두는 캐시는 금지다(KB `concepts/static-wasm-hosting.md`, `reference/netlify/deploy-from-ci.md`).

**플랫폼 사실**(2차 출처만 있음 — 실기 확인 필요)
- **Chrome 설치**:
  - 매니페스트(name·icons 192/512·start_url·display) + HTTPS면 메뉴의 "앱 설치"가 된다.
  - fetch 처리기 요구는 모바일 108·데스크톱 112부터 없어졌다. 자동 설치 안내(prompt)는 아직 fetch 처리기가 필요하다(Chrome 블로그 "Revisiting Chrome's installability criteria").
- **iPhone Safari**:
  - 요소 전체 화면 API가 없다(17.x에서 꺼짐, iPad는 접두어판이 있음).
  - `screen.orientation.lock()`도 안 된다(caniuse "Screen orientation lock" 26.5까지 미지원, WebKit 버그 257695: 잠금은 전체 화면 API가 있어야 함).
  - 방향 읽기·바뀜 이벤트는 16.4부터 된다.
  - 매니페스트 `orientation`을 iOS가 따르는지는 확인 못 함.
  - **홈 화면 앱은 Safari 탭과 저장소(localStorage)가 따로다** — 사장이 실기로 확인(2026-11-02). Safari에서 하던 기록은 홈 화면 앱으로 따라오지 않는다(D4).
- **Android Chrome**: 전체 화면 안에서 `screen.orientation.lock('landscape')`가 된다. 설치 앱의 매니페스트 `orientation`도 따른다.

**계획**
1. **매니페스트** `web/manifest.webmanifest`:
   - `name` "Naïl: Under the Roots", `short_name` "Naïl", `start_url` "./", `scope` "./".
   - `display` "fullscreen"(지원 안 되면 브라우저가 standalone으로 내림), `orientation` "landscape".
   - `background_color` `#1f1724`(로딩 화면), `theme_color` 같은 값.
   - `icons` 192·512 + maskable 512.
   - 개발판은 CI의 sed에서 name에 "(dev)", 별개 `id`(설치 앱이 나란히).
2. **아이콘**: `tools/icons/make_icons.py`에 `web()`을 더한다. 같은 원본에서 `web/icons/icon-192.png`·`icon-512.png`·`maskable-512.png`(안전 영역 80%)·`apple-touch-icon.png`(180).
3. **서비스 워커** `web/sw.js`:
   - 캐시 이름에 빌드 SHA를 넣는다. CI 조립 단계에서 `build.txt`와 같은 SHA를 sed로 넣으므로, 배포마다 `sw.js` 바이트가 바뀌어 새 워커가 깔린다.
   - 설치 때 핵심(`index.html`·`*.js`·`nail.wasm`·`assets/art`·`fonts`·`sfx`·팩 파일 넷)만 미리 받는다(약 5MB, 측정해 적는다).
   - 음악(약 23MB)은 들을 때 받으며 채운다(`music.rs`가 이미 필요할 때 읽는다).
   - `index.html`·`build.txt`는 네트워크 우선 → 실패하면 캐시. 나머지는 이 버전 캐시 우선.
   - 활성화 때 옛 버전 캐시를 지운다.
   - **`skipWaiting`은 쓰지 않는다**: 게임 도중 새 버전 파일이 섞이지 않게, 다음 실행부터 새 판.
   - PR 미리 보기에는 등록하지 않는다(헷갈림 방지).
4. **헤더** `web/_headers` → `dist/_headers`:
   - `sw.js`·`index.html`·`manifest.webmanifest`는 `Cache-Control: no-cache`.
   - `.wasm` Content-Type은 Netlify 기본 확인.
   - 중첩 경로 글롭은 KB 경고대로 따로 확인.
5. **가로·세로**:
   - 터치 기기(`pointer: coarse`)에서 세로면 HTML 위에 **글 없는 회전 픽토그램**(폰이 도는 그림)을 띄운다. 글을 쓰지 않으니 번역이 필요 없다(0172의 픽토그램 원칙).
   - 플러그인 `nail_portrait()`로 게임에 알려 **자동 일시정지**한다(입력 막힌 채 싸움이 흐르지 않게).
   - 한 번 탭하면 "그래도 세로로" 계속할 수 있다. 세로에서도 지금처럼 돈다. 강제하지 않는다.
6. **전체 화면**:
   - 설정의 "전체 화면" 줄을 웹에도 연다. 단 **지원할 때만**(`document.fullscreenEnabled`, 플러그인 `nail_fs_supported`).
   - 사용자가 누른 입력에서 요청한다. `requestFullscreen`은 캔버스가 아니라 `document.documentElement`에 건다(회전 안내·로딩이 보이게).
   - 들어간 뒤 `screen.orientation.lock('landscape')`를 시도하고, 실패는 조용히 무시한다.
   - 빠져나오면(뒤로·Esc·`fullscreenchange`) 설정 표시를 맞춘다.
   - iPhone은 이 줄을 숨기고, 대신 일시정지 안내(2.7)에 "홈 화면에 추가하면 주소창 없이" 한 줄. 문구는 열한 언어.
   - 자동 전체 화면·우회는 하지 않는다.
7. **안전 영역**: `viewport-fit=cover`는 이미 있다. 노치 폰 가로에서 터치 버튼이 노치에 닿는지 보고, 닿으면 `env(safe-area-inset-*)`를 플러그인으로 넘겨 터치 오버레이 여백에.
8. **인라인 스크립트 나누기**(R37): `index.html`의 플러그인 다섯이 길어졌다. `web/nail-host.js`로 옮기면 CI의 `web/*.js` 복사·미리 받기 목록이 단순해진다.

**확인**

  - 덤불·무너지는 천장·흰 실 그물·포자는 적 문단에 한 줄.
- 진행 잠금이 없어, 처음부터 도토·마을 항목까지 다 보인다.

**계획**
- `rooms` 하나를 다섯으로 나눈다. 항목마다 그림 `help::Pic` + `render/help.rs`의 `pic_*` 하나, 실제 구현과 결정 번호를 대조해 쓴다.
  1. **싸움방 넷**: 다 잡기·물결·매복·버티기가 각각 어떻게 끝나는지 + 싸움 막대 + 나타나는 동안 안 맞음 + 넓은 방은 물결.
  2. **방 표지**: 문 안쪽 바닥 그림의 색과 보상 + 붉은 겹테 = 물결·버티기 + 상자는 버티기에서.
  3. **길 위의 것**: 샘(밟으면 회복)·상자(곁에서 공격 버튼)·부술 것·출구(끝방, 버튼으로 내려가기).
  4. **위험물**: 가시뿌리 덤불(걷는 적도 찔림, 박쥐는 안 찔림)·무너지는 천장 예고·포자 구름(밀리지 않는 피해)·흰 실 그물.
  5. **길 지도 칸**: 엘리트(실타래)·샘·굴토끼 굴은 "흰 실에 감긴 옛 굴"까지만(미스터리, 2.1과 같은 기준).
- 같은 말을 두 항목에 쓰지 않는다. 길 지도 칸 설명(`node_*_desc`)과 겹치는 문장은 그쪽에 맡기고 링크하듯 한 줄만.
- **진행 잠금**(R36):
  - `Topic`에 `gate`를 단다. 잠그는 근거는 기록 깃발·통계(예: 처음 굴에 들어가면 `help.rooms`, 흰 실 지대에 닿으면 `help.silk`, 도토를 고를 수 있으면 도토 항목).
  - 처음 열린 항목에 "새" 점을 단다.
  - 새 키는 `help.<id>` 깃발이다(키 이름은 바꾸지 않는다, 0041).
- 글은 열한 언어. 길이는 페이지 나눔(이미 있음) 안에서 한 페이지 3~4줄.

### 2.7 안내와 마을 설명 나누기 → 안내 + 마을 수첩(P2)
**나누는 기준**
- **안내**(일시정지 여덟째 탭) = 조작·규칙·시스템 사용법만.
- **마을 설명** = 장소·시설·물건·이웃·분위기.
- 굴 안의 방은 "어떻게 다루나"라서 안내 쪽(2.6)이다.

**지금 섞인 곳**
- `h_village_d` 한 문단에 다 들어 있다: 큰 나무·실뜨기·꿈·저널(시스템)과 포포 꾸미기·짐(시설).
- 마을 물건·자리를 살펴보는 동작이 없다.
- 이야기 한마디(`village_intro` 등)만 분위기를 말한다.

**계획**
1. **안내 쪽**: `h_village`를 "큰 나무와 재주"·"실뜨기와 꿈"·"저널·짐 꾸리기 규칙" 셋으로 나눈다(규칙만, 장소 묘사 없음). 실뜨기·꿈은 할매가 마을에 온 뒤(`half_ending`)에만 연다 — 엔딩 전 스포일러 방지.
2. **마을 수첩**(새, 2.5의 셋째 탭):
   - 마을 장소·물건·이웃을 한 줄 그림 + 두세 문장 결로 쓴다. 대상은 큰 나무·물웅덩이·모닥불·뿌리 길·실 고리·꾸미기 아홉·이웃 자리.
   - 본 것만 열린다(이웃이 돌아왔는지, 꾸미기를 놓았는지 등 기존 기록으로 판단, 새 키 거의 없음).
   - 할매 칸은 놓아준 뒤에만, 그리고 정체를 말하지 않는 결로(2.1 기준).
3. **월드에서 살펴보기**:
   - 마을에서 꾸미기·큰 나무 둘레·물웅덩이 곁에 서면 기존 말풍선(`Interact`)으로 수첩 첫 문장을 보여 준다.
   - `Interact::Look(Spot)` 하나를 더하고, 수첩과 **같은 표**를 읽는다(내용 한 곳).
4. **데이터 한 곳**: `village_notes.rs`(가칭)에 표 `NOTES { spot, title, body, gate }`. 안내 `help.rs`와 겹치는 문장은 시험으로 막는다(같은 `Tr` 키를 둘이 쓰지 않음).

**완료 기준**
- 안내 탭에 장소 묘사가 없다.
- 수첩에 조작·규칙이 없다.
- 잠금은 기존 진행 기록을 따른다.

### 구현(2026-11-02, release/v0.7) — 2.6·2.7
- **안내 주제 표**(`help.rs`): 주제마다 `id`(기록 키 `help.<id>`)·`gate`(`Option<fn(&Profile) -> bool>`). 목록은 `help::visible`로 기록이 닿은 것만. 잠겼다 열린 주제는 제목 뒤 금빛 점("새", 글이 아니라 모양), 고르면 `help.<id>`가 선다(개발 시나리오는 적지 않는다 — B3).

  - 수입과 비슷해 천천히 쌓인다.
- **이야기 연결**:
  - 반딧불은 "땅속에선 빛이 귀하다"(0016), 큰 나무가 빛으로 재주를 기억한다, 저널 "빛을 돌려주기" → 반딧불 병.
  - 씨앗 화폐는 이야기의 씨앗(도토가 묻고 잊은 씨앗, 참 엔딩의 새싹)과 **연결이 없다**.
  - 0016의 "나중에 심기로 메타 진행"은 만들지 않았다.
- 다회차 식별: `clears.<캐릭터>`·`half_ending`·`true_ending`·`momo_deep`·`doto_deep`·`knots.<캐릭터>`. 따로 NG+ 칸은 없다.

**제안**(화폐를 새로 바꾸거나 반복을 강요하지 않는 쪽만)

| 안 | 내용 | 세계관 근거 | 비용 | 결정 |

### 2.10 할매가 지상으로 올라온 뒤 → 이야기(P3, 결정 필요)
**지금 흐름**
1. 가장 깊은 곳에서 매듭 셋 → 굵은 실 받아치기 → `DeepDone` → `reach_deepest`.
2. 기록: `clears`, 실뜨기 단계, 마을 씨앗, 깃발 하나(반쪽/참/모모/도토).
3. 엔딩 컷씬 → 올라오는 전환(`Ascend`) → 마을에서 한마디 하나.
- 마을:
  - 할매가 'H'에 서고(숨쉬기 칸 둘만), 실 고리(꿈)가 생긴다.
  - 말 걸면 **늘 실뜨기 고르기**로, 그 밖의 말은 없다.
- 할매의 마을 한마디 넷은 `half_ending` 조건 → B1 때문에 참 엔딩만 본 기록에서는 안 나온다.
- 이웃 반응:
  - 보리·모모가 한 줄씩. 참 엔딩 뒤 줄들은 할매를 말하지 않는다.
  - 콩이·토끼풀·수수·도토·집의 Naïl은 할매에 대해 말이 없다.
- 그 뒤의 런: 그대로다.
  - 가장 깊은 곳의 할매는 여전히 묶여 "왔구나…"를 말하고, 같은 엔딩이 매번 다시 나온다.
  - 모모·도토 엔딩 글("언젠가 꼭 찾으러 올게"·"나일이랑 같이 다시 올게")은 토끼풀 가족·참 엔딩 뒤에는 이미 이뤄진 약속이다.
- **어긋남**: `half_5` "실은 물러났지만, 놓아주지는 않았다"인데 할매가 마을로 옮겨 온다. 0037은 반쪽 엔딩 뒤 "쉼터로 돌아간다"였고, replay-brainstorm §2는 실뜨기를 참 엔딩 뒤 "놓는 법을 배운 할매"에 두었다.

**제안하는 뒤 이야기 뼈대**(핵심 설정은 바꾸지 않는다)
1. **반쪽 → 참 사이**: 할매는 마을에 "와 있다". 하지만 실은 아직 깊은 곳에 남아 있다(`half_5`를 살림). 마을의 할매는 눈을 거의 뜨지 않는다(지금 칸). 이웃의 반응은 조심스러움·낯섦.
2. **참 엔딩 뒤**:
   - 할매의 마을 그림을 아직 안 쓴 칸(눈 뜸 4·기쁨 5)으로 바꾼다. 놓는 법을 배운 할매다.
   - 이웃 반응은 받아들임. 실뜨기 말투가 달라진다.
3. **다시 내려간 가장 깊은 곳**(D6):
   - 할매가 마을에 있는데 깊은 곳에도 있는 것을 무엇으로 볼지가 핵심이다.
   - 후보 (a): 깊은 곳의 것은 "남은 실"(실의 꿈처럼 할매의 실이 기억하는 모습) — 만남 카드·첫마디만 회차에 따라 바꾼다.
   - 후보 (b): 그대로 둔다.
   - 추천은 (a). 이미 있는 꿈의 틀을 쓰고 새 설정을 만들지 않는다.
4. **되풀이 엔딩**: 이미 본 엔딩은 짧게(첫 장면 + 마지막 내레이션, 건너뛰기는 그대로). 모모·도토 엔딩의 약속 줄은 이뤄진 뒤 다른 끝줄로(줄 둘씩 × 열한 언어).

**바로 넣을 수 있는 것**(설정과 충돌 없음)
- B1 고침.
- 할매 `CHATTER` 줄을 캐릭터 셋 × 세 줄로. 말 걸면 한마디 → 실뜨기 고르기(또는 고르기 창에 "이야기" 칸). 정체는 말하지 않고 지금의 말투(실·외로움·옛 기억)로.
- 아직 할매에 대해 말이 없는 이웃 다섯(콩이·토끼풀·수수·도토·집의 Naïl)의 `once` 한 줄씩. 반쪽/참으로 갈라 짧게.
- 참 엔딩 뒤 할매 마을 그림 칸 바꾸기(그림은 이미 있음).
- 되풀이 엔딩 짧게.

**결정이 필요한 것**
- D6(깊은 곳의 할매를 무엇으로 볼지).
- D7(`half_5`와 마을 이사의 관계를 글로 이을지).

- 새 엔딩·캐릭터의 운명은 만들지 않는다.
