# 0092. 인트로 바탕을 타이틀 그림으로, 웹 시작 파일은 한꺼번에 받기

- 날짜: 2026-10-26
- 상태: 채택. 사장: "첫 시작 시 예전 타이틀 화면에서 쓰던 백그라운드 이미지가 아직 남아 있는데 잘 어울리는지 모르겠어. 그리고 웹 로딩 시 앞쪽의 진행률은 빠르게 올라가는데 뒷쪽 로딩은 너무 느려."

## 인트로(첫 시작의 세 줄)
- 전: 맨 처음 타이틀의 격자 + 갈색 뿌리 선(`render::draw_title_background`, 월드가 없을 때의 바탕)이 그대로 보였다. 0083의 타이틀 그림과 이어지지 않았다.
- 후: 타이틀 그림(안개·반딧불 포함)을 그리고 그 위를 짙은 어둠(알파 0.9)으로 덮는다. 세 줄이 지나는 동안 어둠을 0.45까지 걷어 타이틀로 이어진다. 그림을 못 읽으면 예전 바탕이 남는다(대비책).

## 웹 로딩
### 잰 것(헤드리스 Chromium, 지연 70ms·9Mbps 흉내)
| | 전 | 후 |
|---|---|---|
| wasm 받기(막대 0~60%) | 1.65초 | 1.65초 |
| 그 뒤(막대 60~100%) | **6.1초**: 폰트 3·그림 26·소리 15 = 44개를 하나씩 `await`. 파일마다 왕복 0.1~0.15초 | **2.7초** |
| 막대 | 다섯 단계라 84%에서 3초 멈춤 | 파일 하나마다 한 칸 |
| 합계 | 7.7초 | 4.4초 |

- 받는 바이트는 많지 않다(그림 0.8MB·소리 0.3MB·폰트 0.75MB). 느렸던 것은 **차례로 받기**였다.

### 결정
- `loading::prefetch(files, after)`: 시작 파일 목록을 한꺼번에 요청한다. 퓨처를 한 `poll_fn`에서 함께 돌리고, 받는 대로 막대를 채운다. 바이트는 캐시에 둔다.
- `loading::bytes/texture/image`: 캐시에서 꺼내 만든다. 목록에 없는 파일은 그때 받는다. 느릴 뿐 틀리지는 않는다.
- 목록은 `Art::files()`·`Sfx::files()`·폰트(`Lang::font_file`)가 각자의 `load`와 같은 이름으로 만든다.
- `loading::step(done, total)`: 단계 수를 상수(STEPS = 5)로 두지 않는다. 그 상수를 맞추던 테스트는 지웠다.
- 새 크레이트는 넣지 않았다(`futures` 없이 `std::future::poll_fn`).

## 더 줄이려면(안 함)
- 컷씬 그림 11장(0.66MB)을 처음 볼 때 읽는다(음악처럼 0081). 지금 측정으로 0.5초 안팎이다.
- wasm(1.49MB) 자체를 `wasm-opt`로 줄인다. 빌드 단계가 하나 는다.
