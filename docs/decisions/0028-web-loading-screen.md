# 0028: 웹 로딩 화면 = 글 없는 걷는 Naïl + 막대, 첫 프레임을 그리면 걷는다

- 상태: 채택 (2026-10-25, 사장 제안 "웹 버전은 초반에 로딩 인디케이터가 필요할 것 같다")

## 결정
1. `web/index.html`이 캔버스 위에 로딩 화면을 덮는다: 게임 배경색, `assets/art/nail.png`의 걷기 4칸(CSS steps 애니메이션, 4배, pixelated), 그 아래 막대. **글은 없다**(플레이어가 보는 글은 i18n.rs에만 — 0013. 이 시점엔 언어·폰트도 아직 없다).
2. 막대: 0~60% = `nail.wasm` 받은 바이트(`fetch`를 감싸 스트림을 세고 같은 바이트로 Response를 다시 만든다), 60~100% = 게임이 알려 주는 준비 단계(`src/loading.rs`: 기본 폰트, 일본어·간체 폰트, 그림, 소리 = 5단계).
3. 게임이 **첫 프레임을 그린 뒤** `loading::ready()` → 0.25초 흐려지며 걷고 캔버스에 초점.
4. `prefers-reduced-motion`이면 걷기 애니메이션을 멈춘다.

## 왜
- 처음 열면 wasm 약 900KB + 폰트 약 720KB(한글 Galmuri만 450KB)를 받고 소리를 합성하는 동안 검은 화면이다. 느린 모바일 회선에선 몇 초 — 멈춘 것처럼 보인다.
- 번들이 wasm을 `fetch` + `compileStreaming`으로 받으므로, 번들을 고치지 않고 `fetch`만 감싸면 진행을 셀 수 있다.
- 압축 전송(gzip/br)이면 Content-Length가 받은 바이트(압축 푼 양)보다 작을 수 있다 → 받은 양으로 키운 추정치로 나누고 95%에서 멈춘다.
- 첫 프레임 전에 걷으면 검은 화면이 한 번 보인다.

## 재검토 조건
- 한글 폰트(450KB)가 가장 크다. 더 빨라야 하면 Galmuri를 게임 글자만 서브셋(일본어·간체처럼)으로.
