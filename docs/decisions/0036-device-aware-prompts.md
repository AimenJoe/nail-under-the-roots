# 0036: 안내 글은 지금 쓰는 장치(키보드·패드·터치)를 따른다

- 상태: 채택 (2026-10-25, 사장 "현재 사용하고 있는 컨트롤러에 따라 안내문이 바뀌는 게 맞지").

## 결정
1. `input::Device { Keys, Pad, Touch }` = **마지막으로 실제로 누른 장치**. 키 → 키보드, 패드 버튼·스틱 → 패드, 화면 터치(새 손가락·스틱·버튼) → 터치.
   마우스 클릭은 바꾸지 않는다 — 모바일 브라우저는 터치마다 가짜 마우스 클릭도 만든다(miniquad simulate_mouse_with_touch).
2. 처음(아무것도 누르기 전, 인트로)은 기기로 짐작: 웹은 `matchMedia("(pointer: coarse)")`(손가락이 주 포인터)면 터치(`nail_device` 플러그인), Android는 터치, 그 밖은 키보드.
3. 버튼 이름 `prompt(Act)`: 키 이름 / 패드 버튼 / 터치 버튼 글자(ATK·DIG·SP·ITEM·<>, 지도는 MENU).
4. 메뉴 동사 `verb(Verb)`: 확인·뒤로·메뉴·걷기·고르기·값 바꾸기·탭·건너뛰기·다시 시작. 키보드 Enter·Esc·WASD·↑↓·←→·Q/E, 패드 A·B·Start·스틱·LB/RB, 터치는 낱말(터치·바깥 터치·여기를 터치·왼쪽 끌기·◀▶·ATK).
5. 글 표는 키 이름을 박지 않고 `{0}` 자리로(건너뛰기·타이틀·설정·탭·장착·튜토리얼 이동·컷씬·쓰러짐·길 지도·가게). 뜻이 달라지는 몇 개만 터치 전용 글(타이틀 "원하는 것을 터치", 탭 넘기기, 길 지도 "터치로 고르고 한 번 더 터치").
6. 컷씬 건너뛰기 안내는 누를 수 있다(터치에는 뒤로가 없어서) — 누르면 뒤로와 같다.
7. 조작 설정 화면(키·패드 다시 붙이기)의 안내는 그대로(키·패드 이야기라서).

## 확인
- 단위 테스트: 장치마다 동사·버튼 이름이 바뀌고 빈 이름이 없다.
- 헤드리스: 데스크톱 타이틀 "↑↓ 고르기 · Enter 확인 · Esc 뒤로", 폰(터치만) 인트로 "터치: 건너뛰기"·타이틀 "원하는 것을 터치"·컷씬 "여기를 터치: 건너뛰기"(누르면 건너뜀).
- 패드는 헤드리스로 못 흉내 내서 단위 테스트만. 사람 확인 필요.
