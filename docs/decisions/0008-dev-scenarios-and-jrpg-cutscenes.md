# 0008: 개발 빌드에 시나리오 선택 메뉴, 컷씬은 JRPG식 인게임 연출

- 상태: 채택 (2026-10-25)

## 맥락
판정과 손맛 조정을 하려면 "원하는 방 구성으로 바로 들어가는" 길이 필요하다. 매번 타이틀 → 컷씬 → 웨이브 1을 거치면 테스트가 느리다. 컷씬은 영상이 아니라 옛 JRPG처럼 인게임 배우가 걷고 아래 대화창에 글자가 찍히는 방식으로 간다는 사장 결정.

## 결정
1. **시나리오**(`src/scenario.rs`): `Scenario` enum과 `LIST`(이름·설명·구성). 타이틀의 "개발" 항목(`dev` cargo feature, 기본 켬)에서 고른다. 일시정지의 "다시 시작"은 현재 시나리오를 다시 만든다. 월드에 `empty()`, `spawn_enemy()`, `auto_waves`가 생겼다.
2. **컷씬**(`src/cutscene.rs`): `Step` 목록(대화·이동·바라보기·대기·등장·퇴장·페이드·흔들림)을 순서대로 재생. 배우 0번은 플레이어(월드 위치를 직접 움직임), 나머지는 컷씬의 임시 배우. 대화창은 아래 전체 폭, 이름표, 초상 자리(그림 없으니 색 네모), 타자 효과(초당 40자), 완료 표시 ▼. 확인으로 넘기고, 뒤로(Esc/B)로 건너뛰면 남은 이동·등장·페이드를 즉시 적용한다.
3. 타이틀 "시작"은 오프닝 컷씬 뒤 웨이브 1. 개발 시나리오는 컷씬 없이 바로 게임("오프닝 컷씬" 항목만 예외).
4. 스크립트는 당분간 Rust 코드(`cutscene::opening`). 데이터 파일(RON/JSON)로 옮기는 것은 컷씬이 다섯 개를 넘을 때.

## 왜
- 테스트 비용이 반복 횟수를 정한다. 시나리오 한 줄 추가로 상황을 재현할 수 있어야 손맛 조정이 돌아간다.
- JRPG식 컷씬은 에셋이 없어도(색 네모) 만들 수 있고, 3/4 뷰(0006)·2방향 스프라이트와 맞다. 영상·일러스트 컷씬은 1인 개발의 콘텐츠 비용을 폭발시킨다.
- 건너뛰기는 처음부터. 판정 테스트에서 같은 컷씬을 열 번 보게 하면 안 된다.

## 비용
- `dev` feature가 기본이라 웹·APK 배포 빌드에도 "개발" 메뉴가 보인다. 공개 배포 시 `--no-default-features`로 뺀다(CI에 플래그 추가).
- 컷씬 스텝이 코드에 있어 작가가 손대기 어렵다. 양이 늘면 데이터화.

## 재검토 조건
- 컷씬에 분기(선택지)·카메라 이동이 필요해지면 `Step`을 확장하거나 데이터화와 함께 재설계.
- 웹에서 `?scenario=` 같은 URL 진입이 필요해지면 JS 글루에 한 줄 추가(miniquad는 URL을 읽지 않는다).
