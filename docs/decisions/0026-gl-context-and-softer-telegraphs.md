# 0026: WebGL 컨텍스트는 안티에일리어싱·투명 배경 끔 / 공격 예고는 더 투명하게

- 상태: 채택 (2026-10-25). 계기: 사장 "아직도 iOS에서 조금 버벅거린다", "빨간 인디케이터가 너무 샛빨갛다, 투명도가 있으면".

## 결정
1. `web/index.html`에서 `#glcanvas`의 `getContext("webgl"/"webgl2")`에 `{antialias: false, alpha: false, powerPreference: "high-performance"}`를 끼운다. 번들 복사본(`mq_js_bundle.js`)은 고치지 않는다.
2. 공격 예고(0025)의 불투명도: 채움 3% → 16%, 테두리 15% → 50%(0025는 6→32%, 25→85%). 색은 조금 덜 짙은 붉은빛, 마지막 깜빡임도 흰 번쩍이 아니라 조금 밝은 붉은빛. 수치는 `render.rs`의 `TELEGRAPH_FILL`·`TELEGRAPH_EDGE`.

## 왜
- 번들은 옵션 없이 컨텍스트를 만들어 브라우저 기본값을 받는다. 헤드리스 측정(아이폰급 844×390, dpr 3): 캔버스 2532×1170, `antialias: true`, `alpha: true`. 매 프레임 300만 픽셀을 4배 샘플로 칠하고 합치는 일은 모바일 GPU에 무겁고(메모리 대역폭), 320×180을 정수배로 키우는 도트 그림에는 아무 이득이 없다. 투명 배경은 페이지와 합성하는 비용만 더한다(배경은 어차피 검정).
- 그리기 호출은 프레임당 20여 번으로 적었다(같은 측정). 글자 아틀라스 다시 올리기는 0024 이후 고쳤다(text-rendering 노트). 남은 큰 비용이 화면 크기 × 샘플 수였다.
- 예고가 바닥을 덮으면 위험 신호가 아니라 화면 색이 된다. 테두리로 "어디", 진하기 변화로 "언제"가 읽히면 채움은 거의 없어도 된다.

## 확인 못 한 것 / 재검토 조건
- 실제 iPhone에서 얼마나 좋아졌는지는 사람이 본다. 저전력 모드면 Safari가 30fps로 낮춘다(끈 상태로 비교).
- 그래도 버벅이면 다음 후보: `high_dpi`를 끄고 CSS `image-rendering: pixelated`로 키우기(캔버스 픽셀 9분의 1), 화면 전체를 덮는 반투명 사각형(어둡게·번쩍임) 줄이기.
