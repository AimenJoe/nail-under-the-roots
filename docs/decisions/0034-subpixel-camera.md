# 0034: 부드러운 카메라 — 렌더 타깃 1px 여분 + 소수점만큼 화면에서 밀기

- 상태: 채택 (2026-10-25, 사람 피드백 "움직일 때 캐릭터가 들썩이는 건 좋은데 화면 전체가 조금 떨리는 것 같아 눈이 피로해").

## 원인(측정)
- 걷는 속도 90px/s = 틱당 **1.5px**. 카메라를 그대로 정수 px로 굴리면 화면 전체가 1px·2px을 번갈아 걷는다(30Hz 떨림). 브라우저에서 프레임마다 카메라 값을 찍어 보니 1,1,1,2,3,3,2… 고르지 않게 움직였다.
- 게다가 렌더러의 `lerp`(그림 위치용)가 **반올림**까지 해서 카메라가 늘 정수였다.

## 결정
1. 카메라는 반올림하지 않고 보간한다. 정수 부분으로 렌더 타깃에 그리고, **소수점 부분은 화면에 올릴 때 화면 px 단위로 민다**(배율 4면 게임 px의 1/4씩). 렌더 타깃은 오른쪽·아래로 1px 크게(321×181) 만들어 민 자리를 채우고, 화면 칸 밖으로 나온 여분은 검정으로 덮는다.
2. 그림(타일·스프라이트)은 렌더 타깃의 정수 격자에 그대로 → 픽셀 크기는 고르게 남는다(KB pixel-perfect-rendering).
3. HUD 막대(체력 핍·굴파기·SP)는 렌더 타깃에서 빼서 화면 패스(`draw_hud_bars`, `ui.rect`)로 — 렌더 타깃에 두면 소수점 밀기에 같이 흔들린다. 번쩍임·페이드 덮개는 여분까지 덮는다.
4. 확인: 브라우저 로그로 밀기 값이 0~4 화면 px로 바뀌는 것, 화면 가장자리에 여분이 안 보이는 것. 사람 확인: 실기에서 눈이 덜 피로한지.

## 대가
- 카메라가 부드러워진 대신, 플레이어 스프라이트는 게임 px 단위로만 움직이므로 화면 위에서 최대 반 게임 px(배율 4면 2 화면 px)만큼 흔들릴 수 있다. 큰 면적(배경 전체)이 떨리는 것보다 작다. 거슬리면 카메라를 플레이어의 반올림 위치에 묶는 방식과 비교한다.
- 걷는 들썩임(`draw_nail`의 bob)은 그대로 둔다(사람이 좋다고 함).
