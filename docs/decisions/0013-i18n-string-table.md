# 0013: 다국어는 언어별 문자열 표 하나. 한국어·영어 먼저, 기기 언어로 시작

- 상태: 채택 (2026-10-25)

## 맥락
사장 요청: 다국어 지원. 그때까지 플레이어가 보는 글 약 120개가 `app`·`equipment`·`cutscene`·`tutorial`·`biome`에 한국어 리터럴로 흩어져 있었다.
폰트는 Galmuri11 Condensed를 KS X 1001 한글 2,350자 + ASCII + Latin-1로 서브셋한 것이다(0007).

## 결정
1. **표 하나**: `src/i18n.rs`의 `Strings` 구조체가 키(필드 이름)이고 언어마다 `static` 하나(`KO`, `EN`). 언어에 키가 빠지면 **컴파일이 안 된다**.
2. **자리표시자**: 숫자가 들어가는 글은 `{0}`, `{1}` + `fill()`. 어순이 달라도 되고, 문장을 조각으로 잇지 않는다. 숫자 모양(소수 자리)은 부르는 쪽이 정한다.
3. **데이터 표는 글 대신 `Tr`(= `fn(&Strings) -> &str`)을 든다**: 무기 이름·설명, 퀘스트, 컷씬 대사, 튜토리얼 힌트, 환경 이름. 그릴 때 `tr()`로 꺼낸다. 월드 로직은 지금 언어를 모른다.
4. **시작 언어는 기기 언어**: 웹은 `navigator.languages`(`web/index.html`의 `nail_locale` 플러그인, wasm-bindgen 없이), 데스크톱·Android는 `sys-locale`(Android는 `persist.sys.locale`). 한국어가 아니면 영어. 설정 → 언어에서 좌우로 바꾸면 즉시 바뀐다(저장은 3단계).
5. **테스트(cargo test)**: 모든 언어의 모든 글이 폰트에 있는 글자로만 되어 있는지(TTF cmap을 직접 읽음), 자리표시자가 언어끼리 같은지, 빈 글이 없는지.
6. **번역하지 않는 것**: 개발 전용 화면(개발 시나리오 목록, F1 디버그 오버레이), 고유명사(Naïl), 키 이름(J/X/ATK, Esc/B).
7. **배치는 늘어날 글을 견디게**: 상태 탭 이름 칸은 가장 긴 이름에 맞추고, 긴 안내는 줄바꿈한다. 새 화면은 두 언어로 스크린숏을 찍어 넘침을 본다.

## 왜
- 키를 원문(한국어 문장)으로 쓰는 gettext 방식은 원문을 고치면 번역이 끊긴다. 고정 키 + 컴파일 검사가 1인 개발에 가장 싸다.
- fluent·rust-i18n 같은 크레이트는 복수형·성별·런타임 파일 로드를 주지만, 지금 두 언어·글 120개에는 의존성과 런타임 실패(키 오타)만 늘린다. 복수형이 필요해지면 그때 바꾼다.
- 서브셋 폰트에서 가장 흔한 사고는 "번역은 들어왔는데 글자가 안 나옴"이다. 테스트가 CI에서 잡는다.

## 비용
- 글 하나를 넣으려면 키를 정하고 두 언어를 다 써야 한다(그게 목적).
- 영어 번역은 Claude 초안이다. 출시 전에 원어민 검수.
