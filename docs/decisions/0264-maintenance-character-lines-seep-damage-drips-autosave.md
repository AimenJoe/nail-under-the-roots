# 0264 — 유지보수 패치: 캐릭터별 상태·대사 검수, 독구름 반응, 동굴 물방울 좌표, 저장 빈도

- 날짜: 2026-11-02
- 상태: 채택(사장 작업 지시 "기존 게임 버그 수정, 캐릭터별 대사 검수 및 KB 현행화" 8항목). 마일스톤 밖 기능은 넣지 않는다 — 고장 고침과 검수.
- 새로 쓴 대사(아래 표)는 기존 줄의 뜻을 유지하고 듣는 이·말하는 이만 맞췄다. **사장 확인 필요**(말투·어감).

## 1. 메뉴 → 상태: 필살기 이름·설명이 늘 Naïl의 것
- 원인: `app/pause.rs draw_status`가 `s.special_name`("드릴 돌진")·`s.special_desc`(드릴 설명)를 바로 썼다. 회피 대기 이름은 이미 캐릭터 표(`stat_dodge_cd`)에서 읽는데 필살기만 하드코딩.
- 고침: `characters.rs` 표에 `special_name`·`special_desc`. 이름은 큰 나무의 특기 칸 글(`tal_chain`·`tal_bury`)을 그대로 쓰고, 설명은 `special_desc_momo`·`special_desc_doto`(열한 언어). 안내 탭 `h_special_d`에도 빠져 있던 도토를 더했다.
- 실행 확인(헤드리스 웹, 개발 시나리오 나일 아레나·모모 아레나·도토 아레나): 이름표가 처음엔 설명만 바뀌고 "드릴 돌진"이 남은 것을 찾아 같이 고쳤다.

## 2. 튜토리얼(오프닝) 첫 등장에서 Naïl이 걷지 않고 미끄러짐
- 원인: `Cutscene::update`가 매 프레임 끝에 `World::freeze()`로 `player.prev_pos = pos`를 맞춘다. 플레이어 그림(`draw_nail`·`draw_kin_player`)은 `pos - prev_pos > 0.05`로 걷기 칸을 고르니 컷씬의 `Step::Move { actor: 0 }` 동안 늘 서기 칸이었다. 다른 배우는 `Cutscene::moving(i)`를 써서 걸었다.
- 고침: 배우 0이 걷는 프레임이면 얼린 뒤 `prev_pos`를 그 프레임에 온 자리로 남긴다(컷씬은 보간 alpha 1이라 그리는 자리는 같다). 걷기가 끝나는 프레임은 그대로 얼려 서기 칸으로 돌아간다. 모모·도토가 배우 0인 장면도 같은 길.
- 이동 뒤 대사·조작 시점: 스텝 순서는 바꾸지 않았다(`player_walks_in_cutscene_move`가 끝 자리 (110, 90)과 서기를 본다).

## 6. 독구름(포자 구름)에 밀리고 멈춤
- 원인: 구름도 몸으로 받는 공격과 같은 `Player::take_damage` → 넉백 속도 170·하던 동작 끊기(`State::Free`, 모으기·먹기 취소)·월드 히트스톱 0.12초·카메라 킥·맞은 자세. 구름 전용 반응 설정은 없었다.
- 고침: `Player::take_seep`(`Recoil::Seep`): 피해·무적 0.8초·번쩍임·소리·흔들림·`Event::Hurt`는 같고, 넉백·동작 끊기·히트스톱·킥·맞은 자세(`Player::knocked`)만 없다. 다른 적·보스·덤불·돌·충격파는 `take_damage` 그대로. 원 설계(0146: 1 피해, 0.3초 뒤부터)에 중독 상태는 없다 — 바꾸지 않았다.
- 시험: `spore_cloud_hurts_without_knockback_or_stagger`(피해·무적 유지, vel < 1, 히트스톱 0, 걸음·휘두르기 이어짐, 같은 자리 덤불은 여전히 밀치고 멈춤).

## 7. 동굴 물방울이 카메라를 따라감
- 원인: `render/fx.rs draw_overhead_falls`가 떨어질 자리를 `cam + hash × 화면 크기`로 뽑았다. 0.8초 떨어지는 동안 카메라가 움직이면 물방울·흙 알갱이가 화면에 붙어 움직였다. 같은 파일의 빛줄기·떠다니는 입자는 이미 월드에 붙어 있다.
- 고침: 자리를 월드 칸(`FALL_CELL` 96px)에서 뽑는 순수 함수 `overhead_falls(time, cam, effects)`. 카메라는 어느 칸을 볼지만 정한다. 밀도는 예전(화면당 여섯 줄기)과 비슷하게, 입자 효과 설정(0141)은 칸 단위로.
- 시험: `overhead_falls_stay_in_the_world_when_the_camera_moves`. 화면으로는 확인 못 함(헤드리스에서 고른 시나리오가 격자 없는 방이었다) → 사람 확인.

## 8. 저장 빈도·신뢰성
기존: 기록(profile)은 이야기 사건마다 곧바로(약 50곳), 런 통계만 바뀐 뒤 10초(`STAT_SAVE_EVERY`), 도감(처음 본 이웃)은 `save_profile`에서만 기록에 들어갔다. 이어하기는 쉼터 도착·가게 닫기·굴 출구·깨어남·타이틀로. 쓰기는 네이티브 임시 파일 → 이름 바꾸기(결과 버림), 웹 localStorage(JS가 예외를 삼킴) — 실패를 아무도 몰랐다.

고친 것:
- **같은 글은 다시 쓰지 않는다**: `profile::put`이 칸마다 저장소에 있다고 아는 글(읽거나 쓰는 데 성공한 글)을 기억하고, 같으면 건너뛴다. 실패하면 비워 다음에 다시 쓴다.
- **주기 저장** `App::autosave`: 게임 화면에서 `AUTOSAVE_EVERY` 5초마다 기록(`save_profile`)과 이어하기(`checkpoint_run`, 장소를 바꾸는 중이면 건너뜀). 바뀐 것이 없으면 쓰기 없음. 런 통계 10초 장치(`stats_unsaved`)는 이것으로 대신했다. 5초 근거: 한 번에 글 몇 KB 만들기 + 비교(1ms 아래), 쓰기는 바뀐 때만, 방 하나 싸움(수십 초)보다 훨씬 짧아 갑자기 꺼져도 잃는 진행이 작다.
- **타이틀로 가기 전**: `App::suspend_run`(반딧불은 마을로 → 기록은 늘 → 이어하기). 전에는 반딧불이 0이면 기록을 적지 않아 그 사이의 통계·도감이 사라질 수 있었다. 오늘의 굴 완주 → 타이틀도 `save_profile`(도감 포함).
- **런을 버리기 전**("다시 하기"·실뿌리, `keep_run_currency`): 재화가 0이어도 `save_profile`. 처음엔 `App::start` 앞에서 적게 했는데, 슬롯을 바꿔 이어할 때(`continue_slot`이 기록을 새 슬롯 것으로 바꾼 뒤 `start`) 옛 월드의 도감 깃발을 새 슬롯 기록에 섞어 쓰는 것을 검토에서 찾아 뺐다 — 기록과 월드가 같은 슬롯일 때만 적는다.
- **PC 창 닫기**: `prevent_quit`로 받아 월드 장면이면 `suspend_run` 뒤 `order_quit`.
- **실패는 실패로**: 네이티브 `store::write`가 폴더 만들기·쓰기·이름 바꾸기 결과를 돌려주고 실패를 `eprintln!`. 웹은 쓴 뒤 같은 플러그인으로 되읽어 비교(`index.html` 그대로 — 캐시된 옛 페이지와도 맞는다). 실패가 시작되면 한 번 알림(`toast_save_failed`, 게임 중 토스트·타이틀 쪽 알림), 이어지는 실패는 다시 알리지 않고 한 번 성공하면 처음으로.
- 형식·칸·키는 그대로(옛 저장 호환). 이어하기가 굴 안의 가방·재화·체력까지 담는 것은 0259의 "타이틀로" 적기와 같은 규칙이 주기로 일어나는 것뿐이다.

남은 위험: 웹 탭을 닫거나 Android에서 앱을 쓸어 끄는 순간은 잡지 못한다(최대 5초치). 네이티브는 fsync를 하지 않는다(이름 바꾸기 교체만 — 메인 스레드 끊김을 피함). 같은 저장을 연 두 탭은 서로의 글을 모른다(전과 같음). 설정(prefs)은 이번에 손대지 않았다(바꿀 때 바로 씀, 실패 무시 그대로).

시험: `file_store_writes_and_reads_back`(같은 글 건너뜀·바뀌면 씀·임시 파일 없음·실패 false·알림 한 번·회복 뒤 다시 씀·이어하기 칸). 헤드리스 웹: 빈 기록 → 시작 → 오프닝 → 튜토리얼에서 localStorage 쓰기를 셌다 — 글이 바뀔 때만 쓰고(15·28·51·77바이트), 16초 가만히·이동에는 쓰기 0, 허수아비를 친 뒤 5.9초에 한 번(77 → 119바이트).
