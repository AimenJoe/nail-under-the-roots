# 0022: 버튼 배치 = 오른쪽 넷이 자주 쓰는 넷, 설정에서 다시 붙이기(웹은 저장)

- 상태: 채택 (2026-10-25, 사장 지시)

## 결정
1. **기본 배치**(패드는 Xbox 글자, 위치 기준):

   | 동작 | 패드 | 키보드 |
   |---|---|---|
   | 공격 | X(왼쪽) | J |
   | 굴파기(회피) | A(아래) | K |
   | 필살기 | B(오른쪽) | L |
   | 아이템 쓰기 | Y(위) | I |
   | 이전/다음 아이템 | LB / RB | Q / E |
   | 지도 | Select | M |
   | 메뉴(고정) | Start | Esc |

   키보드는 패드와 같은 **다이아몬드**(I 위·J 왼쪽·K 아래·L 오른쪽). 겹치던 보조 키(Z·X·Space·R1·R2·L2)는 뺐다.
2. **다시 붙이기**: 설정 → 조작 설정. 동작마다 키 하나·패드 버튼 하나. 확인 → 5초 안에 누른 키/버튼으로. 다른 동작이 쓰던 것이면 **서로 바꾼다**. 이동(WASD·방향키·스틱)·Enter·Esc·Start, 메뉴의 A 확인/B 뒤로/LB·RB 탭은 고정.
3. **화면 안내는 지금 배치를 따른다**: `input::prompt(Act)` — 마지막으로 만진 장치(패드/키보드)의 이름. 튜토리얼 힌트·필살기 설명·퀵 슬롯이 `{0}`으로 받는다.
4. **저장**: 웹은 브라우저 localStorage(`web/index.html`의 `nail_prefs` 플러그인, 정수 칸 18개: 소리·흔들림·언어·배치). 형식 표식이 다르면 무시. 데스크톱·Android는 아직 저장하지 않는다. 고른 언어도 저장(안 고르면 기기 언어).

## 왜
- 액션 로그라이트의 관례가 같다: Hades·Hades II는 X 공격·A 대시·B 캐스트·Y 특수(2차 출처: 공략·위키 표). 손가락이 쉬는 자리(오른쪽 넷)에 손이 가장 자주 가는 넷을 두고, 어깨·가운데는 가끔 쓰는 것.
- 다시 붙이기는 접근성 요구에서 가장 자주 나오는 항목이다(Game Accessibility Guidelines: 불만 1위권, 프리셋 + 사용자 지정, 안내를 배치와 맞추기). 메뉴 조작까지 다 바꾸게 하라는 권고도 있지만, 고정 키가 있어야 "배치를 망쳐서 메뉴로 못 돌아오는" 일이 없다 → 메뉴 확인/뒤로는 고정, 게임 동작만 바꾼다.
- 저장이 없으면 웹에서 매번 다시 붙여야 한다. 문자열 대신 정수 칸으로 주고받아 JS 다리를 가장 작게(언어 플러그인 nail_locale과 같은 방식).

## 재검토 조건
- 닌텐도 배치(A/B 자리 반대) 패드 사용자가 헷갈리면 버튼 이름을 패드 종류별로(웹 Gamepad API id로 추정).
- 데스크톱·Android 저장은 저장 파일(3단계)과 함께.
