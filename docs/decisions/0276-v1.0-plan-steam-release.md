## 무엇이 이미 있나
- PC 셋(Windows zip·macOS 겸용 `.app`·Linux tar.gz)을 CI가 만든다(`build-desktop.yml`, 0240). 실행 파일 옆 `assets`를 찾아서 Steam으로 켜도 그림·소리를 찾는다(`main.rs assets_dir`).
- 저장 자리는 OS마다 한 곳(`profile::data_dir`: `%APPDATA%\nail`·`~/Library/Application Support/nail`·`~/.local/share/nail`), 슬롯 셋 + `prefs.txt`.
- 패드(gilrs)·버튼 그림이 지금 쓰는 장치를 따른다(0036) — Steam Deck의 "패드면 패드 글자만" 조건과 같다.
- 게임 안 라이선스 화면, AI 공개 원칙(0232: 무엇을 어떻게 썼는지 구체적으로).
- 저널(발자국) 목표 표(`journal.rs`)와 이야기 깃발(`profile::key`) — 업적의 조건을 새로 셀 것이 거의 없다.

## 조사(2026-11-04)
- **Rust 연동**: `steamworks` 크레이트(MIT/Apache, `steamworks-sys`가 SDK를 동적으로 읽는다). 업적은 `user_stats().achievement(id).set()` → `store_stats()`, 콜백은 매 프레임 `run_callbacks()`. [2차: docs.rs 문서]
- **SDK 재배포**: Valve SDK 계약은 `redistributable_bin`을 **우리 게임과 함께 실행 파일 꼴로만** 나눠 주게 한다 — 공개 레포에 DLL·`.so`를 커밋하지 않는다. 비공개 에셋 레포(`ASSETS_REPO`)에 두고 Steam 빌드 CI에서만 꺼낸다. 크레이트가 crates.io로 받는 파일은 우리가 커밋하는 것이 아니다(법률 판단은 아님). [1차: SDK Access Agreement 검색 요약]
- **업로드 파이프라인**: SteamPipe를 `steamcmd`로. 커뮤니티 액션 `game-ci/steam-deploy`(도커 — Windows 러너에서 안 됨) 또는 `steamcmd`를 직접. 인증은 **업로드 전용 빌더 계정**(앱 메타데이터 편집·변경 게시 권한만) + 한 번 만든 `config.vdf`를 시크릿으로(가끔 만료 → 다시 로그인). 기본(default) 브랜치로 바로 올리지 말고 `beta` 같은 브랜치로 올린 뒤 사장이 파트너 사이트에서 기본으로 옮긴다. [2차: 액션 README]
- **Steam 클라우드**: Auto-Cloud(코드 없음, 파트너 사이트에서 OS별 저장 경로를 적는다) vs Remote Storage API. 파일이 작고 적으면 Auto-Cloud로 충분 — 우리는 `profile` 몇 KB + `prefs.txt`. [1차: Steamworks Cloud 문서 검색 요약]
- **Steam Deck 검증**: 패드 글자만(키보드 글자 숨김), 가장 작은 글자 1280×800에서 9px 이상(12px 권장), 1280×800 또는 1280×720, 글 입력은 패드로. 글자 크기가 가장 흔한 탈락 이유. 우리 화면은 320×180 × 4 = 1280×720(위아래 40px 띠)이고 글꼴 11px × 4 = 44px라 넉넉하다. [1차: Steamworks Deck 호환 문서 검색 요약 + 2차]
- **업적 수**: 비슷한 로그라이트 10~130개(Into the Pit 10, Neon Abyss 35, Forgotten Mines 50). 갈아 넣는 반복보다 이야기·발견에 붙인 것이 낫다는 쪽(Hades 사례), 이야기 업적은 숨김(스포일러). 완료율 자료는 못 찾음. [2차]
