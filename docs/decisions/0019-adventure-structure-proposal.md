# 0019(제안, 결정 대기): 모험 구조 — 필드 맵 + 절차적 던전

- 상태: **제안**. 사장 답을 받으면 "채택"으로 바꾸고 고른 안을 적는다.

## 맥락
사장 방향: 이 게임은 "JRPG식 모험 + 회피/패링의 전투 재미". 고정된 방에서 웨이브를 막는 지금 구조에서, 화면 이동으로 모험하게 바꾼다. 기본 맵이 있고, 전투는 맵(필드)에서도, 맵에서 들어가는 던전(절차적 생성)에서도.
지금 코드: 방 하나(`room.rs`, 320×180 = 화면 하나), 웨이브(`world.rs`), 개발 시나리오로 시작 구성.

## 제안
1. **필드**: 손으로 만든 타일 맵(지역 여러 개: 꽃 핀 입구 → 뿌리 지대 → 심층, 0010의 환경과 같다). 카메라가 Naïl을 따라 **부드럽게 스크롤**하고 지역 끝에서 멈춘다. 적은 돌아다니다가 가까이 오면 그 자리에서 싸운다(전투 화면 전환 없음). 이웃 NPC·상점·저장 지점이 있다.
2. **던전**: 필드의 입구(굴)에서 들어간다. 들어갈 때마다 **방 그래프를 시드로 생성**: 시작방 → 전투방(들어가면 문이 닫히고, 다 잡으면 열림) → 보물방(장신구) / 휴식방(회복) → 보스방(생명의 씨앗·스토리 무기 `Give`). 방은 화면 한 장(또는 두 장) 크기, 문으로 넘어가면 **화면이 밀리는 전환**. 지도 탭 = 던전 미니맵.
3. **죽으면**: 마지막 저장 지점(필드)에서 다시. 반딧불 일부를 잃는다. 던전은 다시 생성. 장신구·씨앗·무기는 남는다. (로그라이트의 "다시 도전"은 던전 안에서만.)
4. **기술 순서**: ① 방(Room)을 타일맵(충돌 = 타일)으로 일반화 + 카메라 + 시험 필드 하나 ② 필드 ↔ 던전 입구 전환 ③ 던전 생성기(방 그래프·문·클리어·보물) ④ 저장(3단계 범위였던 것을 앞당김). 웨이브 모드는 개발 시나리오로 남긴다(손맛 시험장).

## 질문
- A. 필드 카메라: **연속 스크롤(추천, 비밀의 성전·젤다 신들의 트라이포스 계열)** / 화면 단위 넘김(젤다 1·아이작).
- B. 던전 방: **화면 크기 방 + 밀기 전환(추천, 전투 공간이 읽기 쉽다)** / 큰 방 스크롤.
- C. 죽음 규칙: 위 3번(저장 지점, 반딧불 일부 잃음)이면 되는지.
- D. **패링은 아직 없다.** 제안: 적의 공격이 닿기 직전(0.12초 창)에 공격을 맞추면 튕겨낸다 — 돌격형은 멈칫(큰 경직), 투사체는 되돌아간다. 성공하면 SP가 크게 찬다(0018 필살기와 연결). 굴파기(회피)는 무적으로 피하기, 패링은 맞받아치기 — 둘의 역할을 나눈다. 별도 버튼(R2/K?) 대신 "공격 타이밍"으로 할지, 방패/막기 버튼을 둘지.

## 왜(제안 이유)
- 연속 스크롤 필드는 JRPG의 "걸어서 모험" 느낌이 가장 강하다. 던전은 방 단위가 전투 공간·문 잠금·생성기를 단순하게 만든다(방 = 지금의 Room과 같은 단위라 전투 손맛을 그대로 옮긴다).
- 저장 지점 + 던전 재생성은 JRPG의 진척과 로그라이트의 반복을 한 게임에 같이 둔다.
