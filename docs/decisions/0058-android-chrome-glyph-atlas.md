# 0058: 어중간한 dpi에서도 글자를 작게 굽는다 — Android Chrome 검은 글자

- 상태: 채택 (2026-10-25).
- 사장: v0.1.0을 Android Chrome에서 열자 "폰트가 검은색으로 나온다. 모양은 글자인데 뭉개졌다(그림자·외곽선 같은). iOS에서는 잘 보인다".

## 원인
- `ui::glyph_plan`은 "12px의 정수배로 굽고 정수배로 키우기"가 안 되면 화면 크기로 구웠다(0034 무렵).
  - macroquad는 `ceil(font_size × dpi)` 물리 px로 굽는다(text.rs). 우리 쪽 조건은 `font_size = 굽는 크기 / dpi`가 딱 정수여야 했다.
  - Android 폰에 흔한 dpi 2.625·2.75·3.5에서는 이 조건이 거의 안 맞는다.
- 그래서 dpi 2.625·배율 2에서 글자 하나를 63px로 구웠다. 한국어 표 글자를 미리 구우면 글자 아틀라스가 **4096²(64MB)**까지 컸다(헤드리스에서 WebGL `texImage2D`를 세어 확인).
- 큰 아틀라스는 정밀도에서 깨진다.
  - macroquad 기본 셰이더의 텍스처 좌표는 `varying lowp vec2 uv`다(quad_gl.rs).
  - 폰 GPU의 낮은 정밀도로는 4096 텍스처에서 글자 칸을 정확히 못 집는다 → 뭉개진 글자.
  - iOS(dpi 3)는 12px로 구워 아틀라스가 1024²라 멀쩡했다.
- 헤드리스(SwiftShader)는 정밀도를 다 지켜 재현되지 않는다. 아틀라스 크기로 원인을 좁혔다. 실기기 확인은 사람 몫이다.

## 결정
1. 굽는 크기 계산을 macroquad 규칙(`ceil`)에 맞춘다. `ceil(k × dpi) = 12m`인 정수 k를 찾는다.
2. 고르는 순서:
   1. m ≤ 4이고 키우는 배가 정수인 가장 작은 m.
   2. 없으면 정확히 구워지는 가장 작은 m으로 굽고, **정수가 아닌 배**로 키운다(Nearest).
   3. 그것도 없으면 예전처럼 화면 크기로 굽는다.
   - 예: dpi 2.625면 24px로 굽고 2.625배.
3. 정수가 아닌 배라 글자 픽셀 폭이 조금 고르지 않다. 그런 dpi에서는 화면 전체(렌더 타깃)가 이미 그렇다. 뭉개짐보다 낫다.

## 확인
- 단위 테스트: dpi 10가지 × 배율 5가지에서 "굽는 크기 × 배 = 화면 크기"이고, 굽는 크기가 macroquad가 실제로 굽는 크기와 같다.
- 헤드리스 아틀라스 크기:

  | 경우 | 전 | 후 |
  |---|---|---|
  | 2.625, 한국어 | 4096² | 1024² |
  | 1.25 | 2048² | 1024² |
  | 2.75·3.5 | — | 2048² |
  | 1·2·3 | 그대로 | 그대로 |

- 2.625 화면 글자는 선명했다.
- 사람 판정이 남았다: Android Chrome 실기기에서 글자가 제 색으로 나오는지.
