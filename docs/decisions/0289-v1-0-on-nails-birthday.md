# 0289. v1.0은 나일의 생일(2026-11-10)에 — 상점판은 출시 대기, 나오면 v1.0.x

- 날짜: 2026-11-10
- 상태: **채택**(사장 2026-11-10: "Nail 쪽은 1.0 릴리즈 해주고, 정식 출시일 11월 10일, 나일의 생일. 게임 홈페이지에 넣어줘. 나머지 스토어들은 아직 출시대기 중이지만.. 생일을 그냥 넘어갈 순 없으니까")
- 바꾸는 것: 0284 "정한 것 1"의 "첫 상점이 나갈 때 v1.0을 닫는다"

## 결정
1. **v1.0.0을 2026-11-10에 낸다** — 정식 출시일 = 나일의 생일. release/v1.0 → main + 버전 1.0.0(`version_code` 97) + `docs/releases/v1.0.0.md`. 웹·Android·PC 묶음(Release)이 v1.0.0이 된다.
2. **상점판(Epic PC → Steam)은 출시 대기**: 나가는 판은 `v1.0.x` 패치로 낸다. 상점마다 할 일(등록·업로드·검토)은 0276·0284 그대로. v1.0 마일스톤 갈래(`release/v1.0`)는 상점이 다 나갈 때까지 작업 갈래로 둔다.
3. **공식 페이지**: 첫 화면 사실 줄에 "정식 출시 2026-11-10", "다음" 칸을 "정식 출시 — 11월 10일, 나일의 생일에"로(두 언어), 소식 기본값에 v1.0.0·v0.9.2·v0.9.1.

## 왜
- 정식 출시일을 숫자로 남길 날이 있다면 그것은 나일의 생일이다(사장). 상점 검토 일정은 우리가 정할 수 없어, 날짜를 상점에 묶으면 이 날을 놓친다.
- 버전은 하나로 둔다(0284): 상점판도 같은 v1.0.x라서 무엇이 어디에 나갔는지 헷갈리지 않는다.

## 확인
- `release/v1.0` CI(deploy-web·build-android·build-desktop·build-ios·smoke-web) 초록인 커밋 위에 버전만 올림.
- 공식 페이지: 한국어·영어 × 1280·390·320px 넘침 없음(배포본 `--stamp`로).
