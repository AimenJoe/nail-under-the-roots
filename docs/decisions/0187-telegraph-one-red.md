# 0187. 적 예고 색은 붉은 계열 하나 — 받아칠 수 있는지는 모양으로

- 날짜: 2026-10-28
- 상태: 채택. 0160·0176~0186의 두 색(황금 = 받아칠 수 있음, 진홍 + X = 피해야 함)을 바꾼다. 면·외곽선 = 채움(0186)·자라는 방향(0185)은 그대로.
- 사장: "붉은 계열로 하자."

## 왜
- **황금은 풀밭에서 흐렸다.** 외곽선 밑의 어두운 띠를 뺀 뒤(0186) 황금 0.75는 밝은 초록과 비슷한 밝기라 섞여 올리브색으로 보였다. 붉은색은 초록의 보색이라 같은 투명도에서도 바닥과 갈린다.
- **"위험하다"는 한 색이면 된다.** 예고는 모두 "여기 있으면 맞는다"이다. 받아칠 수 있는지는 두 번째 정보이고, 이미 모양이 갈라 준다 — 곧게 오는 공격은 **띠**(돌진·던지기·혀·실 가닥·할매 당기기, 모두 받아칠 수 있음), 둘레 공격은 **가운데 X가 있는 원**(내려앉기·포자·발 구르기·떨어지는 돌, 모두 피해야 함). 0160이 색과 X를 겹쳐 쓴 것은 색약 대비였는데, 모양만으로 이미 둘이 완전히 갈린다.

## 결정
- `render/fx.rs`: `TELEGRAPH_EDGE_RGB`·`PARRY_EDGE_RGB` → `TELE_RGB`(붉은 계열 1.0·0.32·0.36) 하나. `draw_tele_lane`·`draw_tele_disk`는 색을 받지 않는다.
- 안내: `h_parry_d`의 "(황금 띠)" → "(띠 모양 예고)", `h_enemy_d`의 색 설명 → "띠는 받아칠 수 있고, 가운데 X가 있는 원은 피해야 한다"(열한 언어, CJK 폰트 다시 만듦). 안내 그림은 같은 함수라 따라온다. 받아치기 그림의 불똥 같은 황금색은 예고가 아니라 그대로.

## 확인
- `cargo test` 171개. 헤드리스: 시나리오 13(풀밭, 여러 적)에서 붉은 띠·원이 바닥과 갈림, 안내 그림에서 다 차면 한 색. `cvd.py`: 1·2형에서 붉은 면은 어두운 면으로, 흑백에서도 바닥보다 어둡다 — 모양(띠·X)이 남는다.

## 사람이 볼 것
- 받아칠 수 있는 띠와 피해야 하는 원을 모양만으로 바로 가를 수 있는지. 붉은 지대(뿌리·심층)나 붉은 이펙트 위에서 묻히지 않는지.
