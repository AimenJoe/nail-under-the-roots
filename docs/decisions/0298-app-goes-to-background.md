# 0298. 앱이 내려가면 — 일시정지 창 + 적기, 웹은 소리도 멈춘다

- 날짜: 2026-11-19
- 상태: **채택**(사장 2026-11-19: "앱이 백그라운드로 내려갔을 때 처리는 어때?" → "응 고치자")
- 바탕: 0265(일시정지가 저장 지점 — `open_pause`가 `save_progress`), 0269(웹 세로 안내면 일시정지), 0295(Google Play), 앱인토스 게임 체크리스트("백그라운드로 전환되면 사운드 즉시 종료", 2026-11-19 읽음)

## 고치기 전(코드로 확인)
게임에는 백그라운드 처리가 없었다. 엔진이 해 주던 것만:
- **Android**: macroquad가 onPause/onResume에서 오디오를 멈추고 켠다(`window_minimized_event`의 `#[cfg(target_os = "android")]`). 게임 코드는 그리기(`draw`) 안에서만 돌아 화면(surface)이 사라지면 멈춘다. 누르던 키·터치는 놓는다.
- **웹**: 탭이 숨으면 브라우저가 프레임을 멈춰 게임도 멈추지만, 번들은 숨김을 게임에 "포커스 잃음"(`wasm_exports.focus`)으로만 넘기고 **소리는 그대로** — 휴대폰 브라우저에서 탭을 바꿔도 음악이 났다.
- **iOS·PC**: 엔진이 최소화 사건만 낸다. PC는 최소화해도 게임·소리가 계속될 수 있다.
- 공통: 돌아오면 그 프레임부터 싸움이 이어진다(손이 오기 전에 맞는다). 돌아온 첫 프레임 시간은 `MAX_FRAME_DT` 0.25초로 잘린다.

## 고친 것
1. **내려가면 일시정지 창**(`src/app.rs` `Away`): macroquad 입력 구독 하나로 엔진의 "최소화" 사건(Android onPause, iOS 비활성, 웹 탭 숨김·창 포커스 잃음, PC 최소화)을 듣고, 게임 장면(`Scene::Game`)이면 `open_pause` — 그 안의 `save_progress`가 기록(싸움 중) 또는 기록 + 이어하기(그 밖)를 적는다. 소리는 내지 않는다(돌아온 순간 확인음이 나지 않게). 컷씬·메뉴는 이미 입력을 기다리니 그대로.
   - Android는 onPause 뒤 화면이 사라지기 전 프레임에서 적힐 때가 많지만 보장은 없다 — 그래도 돌아오면 일시정지 상태다.
2. **웹 소리**(`web/nail-host.js`): 번들은 AudioContext 클래스를 미리 읽어 둬 생성자를 못 바꾸니, 소리마다 부르는 `createGain`에서 컨텍스트를 모아 숨으면 `suspend`, 보이면 `resume`(`pagehide`·`pageshow`도). iOS처럼 돌아와서 막히면 다음 터치·키에서 다시 깨운다.

## 시험
- `tools/test/smoke.js` `bg:` — 탭 숨김(visibilityState를 덮고 사건) → 컨텍스트가 `suspended`, 보이면 `running`, 그다음 Esc가 **닫는** 소리(손으로 연 멈춤을 닫을 때 소리와 같고 여는 소리가 아님) = 일시정지 창이 열려 있었다. 자동 일시정지를 끈 빌드로는 이 줄이 실패하는 것을 봤다(2026-11-19).
- `tools/test/android-smoke.sh` — 시작 뒤 홈 키 → 5초 → 다시 앞으로 → 화면 `3-back.png`·살아 있나.

## 하지 않은 것
- PC 최소화 때 소리 끄기(일시정지 창의 곡은 그대로 — 상점 PC 게임은 흔히 그대로 둔다, 바라면 설정으로).
- 웹 숨김 순간의 동기 저장: 숨으면 프레임이 멈춰 앱 상태에 닿을 수 없다(KB `concepts/roguelite-save-slots-and-continue.md`). 웹은 포커스를 잃는 순간(대개 숨기 전)에 일시정지 창 → 적기가 돈다.
