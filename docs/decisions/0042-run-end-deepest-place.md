# 0042: 런의 끝 — 길 셋을 지나 가장 깊은 곳, 엔딩, 타이틀

- 상태: 채택 (2026-10-25). 사장 "필요한 것들 차근차근 만들면 됨". 0040 순서 2(엔딩 연결)다.

## 결정
1. **한 런 = 필드 + 길 3개**(`tuning::FINAL_STAGE = 3`).
   - 셋째 길의 보스 칸은 길 지도에서 **"가장 깊은 곳"**으로 보인다(이름·설명).
   - 그 주인을 이기고 출구를 밟으면 쉼터가 아니라 `AdvEvent::Deepest`가 온다.
   - 지금 길이로 10~15분 런(concept)에 맞는지는 판정 플레이로 본다. 숫자는 tuning 한 곳이다.
2. **엔딩 고르기**(0037):
   - 참 엔딩 조건(`momo` = 모모가 돌아옴, `doto_memory` = 도토가 씨앗 자리를 기억해 냄)이 다 서 있으면 참 엔딩 + 에필로그, 아니면 반쪽 엔딩(누룩 할매).
   - 지금은 조건을 세우는 곳이 없어서 늘 반쪽 엔딩이다. 모모·도토가 생기면 그 보스가 깃발을 세운다.
3. **런이 끝난다**: 엔딩 컷씬이 끝나면(건너뛰어도) 타이틀로 간다.
   - 기록에 캐릭터별 클리어 수(`clears.Mole`)와 엔딩 깃발을 남긴다(첫 시작만).
4. **반쪽 엔딩 뒤 첫 런**에 포포가 한 번 말한다: "가장 깊은 곳까지 갔었다며? …그 할머니, 많이 외로웠나 봐."
   - 런 사이 한마디 표에 조건 셋으로 둔다. 조건이 가장 구체적이라 다른 새 런 줄보다 먼저 나온다.
5. 개발 시나리오: "마지막 쉼터"(셋째 길), "가장 깊은 곳"(바로 반쪽 엔딩 → 타이틀, 기록 없음).

## 왜
- 끝이 없으면 다회차가 없다. 실뜨기·클리어 수·엔딩 뒤 이야기가 모두 "한 런을 끝냈다"에 기댄다.
- 엔딩 컷씬은 이미 있다(0039). 조건 깃발만 비워 두면 모모·도토를 만들 때 연결 코드는 바뀌지 않는다.

## 확인
- 단위 테스트: 마지막 길 보스 출구 → `Deepest` 한 번, 쉼터로 가지 않음. 반쪽 엔딩 뒤 한마디 고르기.
- 헤드리스: 개발 "가장 깊은 곳" → 반쪽 엔딩(내레이션·할매) → 타이틀.
- 실제로 길 셋을 지나 끝까지 가는 플레이는 사람 판정이다.
